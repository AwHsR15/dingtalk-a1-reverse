# 研究总览与当前结论

更新：2026-09-25。本页与新版专题报告优先于历史笔记中的阶段性表述。

## 研究对象与证据

- 自有日本销售版 TALIX & DingTalk A1；不将日版结果自动推广到所有地区、型号和固件。
- 当前静态分析：官方Android 8.5.8.3；另有历史APK/H5快照，版本分别标注。
- 历史设备固件记录：`V1.6.88-202601291628`。
- **静态确认**表示客户端代码存在；**历史实测**表示记录中的设备已通过；**离线验证**表示样本/合成测试通过；三者均不自动代表本次发布的SDK已完成真机验收。

## 已知能力和边界

| 范围 | 已研究成果 | 当前边界 |
| --- | --- | --- |
| BLE | FE3C服务、FE1C写、FE1B通知；8字节应用头；跨ATT分片重组 | characteristic handle不是所有连接的固定值，应发现UUID |
| 鉴权 | 0x0008随机挑战→本地AES应答→0x0133连接；历史独立客户端返回200 | 需要该卡认可的deviceSecret；未完成纯本地首次激活 |
| 多手机 | 凭据可迁移到其他手机/平板；运行阶段不要求root | 多手机用同一卡不等于多张卡共用密钥 |
| 设备状态与控制 | 状态、文件列表、参数设置、录音相关命令及回调 | enum/方法存在不保证该固件支持每一项 |
| 右键 | aikey_option=1000/1001；历史测试覆盖按住送音频、持续录音开始/停止路径 | 不是任意按键脚本；动作也受睡眠、同步和业务状态影响 |
| 左键 | 未发现官方可配置接口 | 已排除出自定义开发目标 |
| 音频流 | 0x0117；同一消息可能含多帧；序号增量需结合帧数判断 | 不能把消息数当音频帧数；回调byte[]也不能一律当PCM |
| 文件 | BLE同步、补包状态、BABA/DTYJ头部和变体；历史完整文件下载 | 中断、缺块、错误完成须单独验收 |
| 加密 | 历史33文件样本显示按文件区分加密；解密/转换入口已定位 | 不能认定所有文件明文或所有文件密文；不把转换等同解密 |
| 官方SDK | 两个.so、15个Java文件、42个native入口；9个核心源可编译JAR | 新提取版本尚未在独立App完整实机验收 |
| 定时 | 0x011A及字段、排序、时区/时间换算相关调用已追踪 | 官方要求cap_schedule≥2，历史本卡为1；离线卡内执行未证实 |
| Wi-Fi快传 | 开AP与业务流程线索 | 完整传输和恢复未做本轮端到端验收 |
| 官方云 | 11个相关服务、90个非升级方法、185个关联模型的静态索引 | 逻辑LWP路由不是可直接curl的公开HTTP API；权限/会话不可由复制函数获得 |
| USB/固件 | 已有USB与平台识别研究 | 手机有root不等于录音卡有root；没有完成固件读取/修改/重新刷写 |

## 官方后台机制的边界

1. **设备本地层**：BLE字节流、命令/事件、随机挑战、文件和音频处理。
2. **宿主适配层**：Android蓝牙、队列、生命周期、目录、凭据、状态与错误处理。
3. **账号业务层**：绑定设备、查询deviceSecret、组织/权益、云文件、转写和纪要任务。
4. **界面层**：H5、Activity及展示。本仓库的官方提取包不包含它。

原生库可以承担复杂音频/协议算法，宿主仍需提供正确输入和回调环境。账号服务没有被打包成一个自动授权的离线模块；自己的ASR、翻译、总结和工作流可以消费本地输出，替代相关云端业务。

## 对旧记录的更正

- “全部解出”“100%”“仅剩封装”等历史措辞不能作为总完成度；以上表和最新专题边界为准。
- 不能把逆向研究和直接复用官方二进制整体称为clean-room实现；这是两条不同接入方式。
- 已证实通过设备信息查询取得deviceSecret；尚未证明它必然在首次绑定时生成或更换。
- `did`是手机客户端登录标识；云接口的`deviceId`是卡的设备ID，两者不同。
- 外部项目报告过另一张卡使用同一密钥得到501；这是[外部实测](https://github.com/Shawn-TKD/dingtalk-a1-pc-tools)，不是本项目新增的两卡对照实验。
- 新版客户端存在自动生成did的代码；这不等于任意固件必然接受任意did。企业ID也不应无依据地宣称无关。
- 当前卡内定时、全新用户无root取得密钥、新版SDK完整运行仍未闭合。
